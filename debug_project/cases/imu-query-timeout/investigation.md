# Investigation: YESENSE startup queries time out while streaming works

## Reproduction Baseline

- Steps: boot the flashed FreeRTOS gateway with the IMU connected to UART12.
- Input/workload: IMU continuously outputs its configured binary stream at 460800 8N1.
- Expected result: five query replies decode before HDMA starts.
- Actual result: five timeouts; HDMA then decodes roughly 200 frames/s.
- Reproduction rate: 5/5 query classes in the supplied boot log.
- Observation window: startup plus the first six heartbeat reports.

## Known Facts and Constraints

- PF17 RX, UART clock, and the configured baud rate are proven sufficiently correct
  by valid continuous frames with increasing transaction IDs.
- A timeout currently means only "no accepted query response"; it does not reveal
  whether polling received bytes or rejected a candidate response.
- Query requests use the v2.3 interaction frame and are read-only.
- Querying occurs before HDMA channel 30 is configured; streaming starts correctly
  immediately afterward.

## System and Failure Path

`yesense_query_build -> uart_send_data(PF16) -> IMU RX -> IMU TX ->
uart_try_receive_byte(PF17) -> yesense_query_parser_push -> device info print`.

Last known-good state: `uart_send_data` reports success and startup continues.
First observable bad state: no response is accepted within 50 ms. The current log
does not locate the fault more narrowly.

## Hypotheses

| ID | Hypothesis | Supporting evidence | Falsifier | Next experiment | Status |
| --- | --- | --- | --- | --- | --- |
| H1 | Polling RX sees no bytes before DMA | DMA is not configured yet | Nonzero polling RX bytes and valid stream frames during the same window | Count bytes and decode stream frames during each query | rejected |
| H2 | PF16 request does not reach the IMU RX input, or that input/electrical interface is unavailable | All independent query classes fail while one-way streaming works | A valid query-class reply or verified request waveform at the IMU RX pin | Measure PF16 and the IMU RX pin during boot | strongest remaining |
| H3 | Reply arrives but interaction parser rejects its operator/length/checksum | Request and stream share the same header and timeout hides parser errors | Zero query format/checksum events while valid streams continue | Expose parser outcomes per query | rejected |
| H4 | 50 ms is insufficient | Device could defer reply behind streaming output | RX trace shows a late but valid reply | Do not extend timeout until H1-H3 are distinguished | open |
| H5 | Query bytes are encoded incorrectly | All commands are newly implemented | Exact frames match the v2.3 bit layout, checksum formula, and vendor examples | Compare all five generated byte sequences with the manual | rejected |
