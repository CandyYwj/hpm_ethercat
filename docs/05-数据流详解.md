# 数据流详解

本文重点回答“数据在三端之间到底经过了哪些缓冲区和函数”。

## 1. 关键数据对象

先看最核心的几个缓冲区。

### 固件侧

- `g_pdo_output_buf[60]`
  - 方向：`RDK -> HPM -> Jetson`
  - 来源：`APPL_OutputMapping()`
- `g_pdo_input_buf[60]`
  - 方向：`Jetson -> HPM -> RDK`
  - 去向：`APPL_InputMapping()`
- `g_jetson_to_rdk_ring`
  - 方向：TSN RX IRQ 到主循环之间的解耦队列
- `recv_buff[TSN_RECV_DEEP][TSN_RECV_LENGTH]`
  - TSW RX DMA 缓冲区
- `g_tsn_tx_buf[...]`
  - TSW TX DMA 缓冲区，里面同时放 TX 头和以太网帧

### RDK 主站侧

- `sl->outputs`
  - 主站写给从站的 PDO 输出区
- `sl->inputs`
  - 从站回给主站的 PDO 输入区

### Jetson 侧

- `frame[]`
  - 原始 socket 发包/收包缓冲

## 2. 数据流 A：RDK -> HPM -> Jetson

这是 EtherCAT 输出方向。

## 2.1 RDK 侧构帧

`ecat_gateway_test.c` 中：

1. `prepare_output_frame()` 取得 `sl->outputs`
2. 把它强转成 `gateway_pdo_frame_t *`
3. 填充：
   - `hdr.type`
   - `hdr.length`
   - `hdr.flags`
   - `payload`
4. `ecx_send_processdata()`

此时数据进入 EtherCAT 帧，并通过 SOEM 发往从站。

## 2.2 ESC/SSC 接收

从站收到输出 PDO 后，SSC 在 `MainLoop()` 内部触发：

- `APPL_OutputMapping(UINT16 *pData)`

这里的 `pData` 就是 ESC DPRAM 中映射后的输出区。

当前代码动作：

```c
memcpy(g_pdo_output_buf, (uint8_t *)pData, 60);
g_pdo_output_updated = true;
```

结果：

- EtherCAT 输出数据被搬到桥接层缓冲区。

## 2.3 桥接层轮询发往 TSN

下一次主循环执行到 `gateway_bridge_poll()` 时，会调用：

- `gateway_forward_ecat_to_tsn()`

它的处理顺序：

1. 检查 `g_pdo_output_updated`
2. 读取 `g_pdo_output_buf` 的 `gateway_header_t`
3. 限制 `payload_len <= 56`
4. 过滤合法 type
5. 在 `g_tsn_tx_buf` 头部构造 `tx_hdr_desc_t`
6. 在 `g_tsn_tx_buf + TSW_SOC_SWITCH_HEADER_LEN` 后构造以太网帧：
   - 目的 MAC = `g_jetson_mac`
   - 源 MAC = `g_cpu_mac`
   - EtherType = `0x88B5`
   - 复制 4 字节网关头和 payload
7. 如果帧不足 60 字节则补零
8. 调用 `tsw_send_frame_check_response(...)`

至此，PDO 已经被转成 TSW 可发的 DMA 帧。

## 2.4 Jetson 收到原始帧

Jetson 侧 `receive_from_board.c`：

1. `recvfrom()`
2. 过滤 EtherType `0x88B5`
3. 从 `frame + 14` 解析 `gateway_header_t`
4. 打印 payload

所以用户在 Jetson 看到的是“原始以太网帧里的网关内容”，不是 IP/UDP/TCP。

## 3. 数据流 B：Jetson -> HPM -> RDK

这是 EtherCAT 输入方向。

## 3.1 Jetson 侧构造原始帧

`send_to_board.c` 中：

1. 构造 Ethernet header
   - Dst MAC = 板子 CPU MAC
   - Src MAC = 本机 MAC
   - EtherType = `0x88B5`
2. 在 `frame + 14` 填入 `gateway_header_t`
3. 在后面拷贝 payload
4. `sendto()`

## 3.2 TSW RX DMA 收包

TSW 收到发给 CPU MAC 的帧后，通过 RX DMA 写入某个：

- `recv_buff[id]`

帧实际起始位置不是 `recv_buff[id][0]`，而是：

- `recv_buff[id][16]`

前 16 字节是 TSW 自己的接收头。

## 3.3 IRQ 侧做轻处理和入队

中断 `gateway_tsn_rx_isr()` 执行：

1. 取 DMA 响应
2. 得到 `id` 和 `len`
3. `frame = &recv_buff[id][16]`
4. 检查 `frame[12..13]` 的 EtherType
5. 如果是网关帧：
   - `gateway_update_jetson_mac(frame + 6)`
   - 取 `frame_len = len - 16`
   - `gateway_ring_push(&g_jetson_to_rdk_ring, frame, frame_len)`
6. 重新提交接收描述符

这里有两个重要副作用：

### 副作用 1：学习 Jetson MAC

`frame + 6` 是源 MAC。学到后，固件后续 `ECAT -> TSN` 可以把数据正确回发到这个 MAC。

### 副作用 2：中断不直接写 PDO

这样避免中断里做太重的 SSC 相关动作。

## 3.4 主循环出队并写入 PDO 输入缓冲区

`gateway_bridge_poll()` 中会调用：

- `gateway_forward_tsn_to_ecat()`

它做的事情：

1. 从 `g_jetson_to_rdk_ring` 弹出一帧到本地 `frame[1522]`
2. 检查长度和 EtherType
3. 计算 `copy_len = frame_len - 14`
4. 如果 `copy_len > 60`，截断到 60
5. `memset(g_pdo_input_buf, 0, 60)`
6. `memcpy(g_pdo_input_buf, frame + 14, copy_len)`
7. `g_pdo_input_updated = true`

这里决定了当前工程的一个硬约束：

- TSN 进来的网关内容进入 EtherCAT 前最多只保留 60 字节
- 其中真正业务 payload 最多 56 字节

## 3.5 SSC 把输入缓冲区映射到 ESC

下一次 `MainLoop()` 需要更新输入 PDO 时，会调用：

- `APPL_InputMapping(UINT16 *pData)`

逻辑：

1. 如果 `g_pdo_input_updated`
   - `memcpy((uint8_t *)pData, g_pdo_input_buf, 60)`
   - `g_pdo_input_updated = false`
2. 否则清零 60 字节

此时数据从 MCU RAM 进入 ESC 输入映射区。

## 3.6 RDK 主站读回

RDK 的 `cyclic_task()` 在下一周期：

1. 调用 `ecx_receive_processdata()`
2. 读取 `sl->inputs`
3. 强转成 `gateway_pdo_frame_t`
4. `print_gateway_frame(...)`

到这一步，Jetson 发来的数据才会出现在 RDK 终端上。

## 4. 数据流里的状态位和计数器

当前工程里有几个关键状态位。

### `g_pdo_output_updated`

- 由 `APPL_OutputMapping()` 置位
- 由 `gateway_forward_ecat_to_tsn()` 消费并清零

说明有新的 EtherCAT 输出待转发。

### `g_pdo_input_updated`

- 由 `gateway_forward_tsn_to_ecat()` 置位
- 由 `APPL_InputMapping()` 消费并清零

说明有新的 TSN 输入待送给 EtherCAT 主站。

### `g_ecat_to_tsn_count`

成功完成一次 `ECAT -> TSN` 转发就加一。

### `g_tsn_to_ecat_count`

成功完成一次 `TSN -> ECAT` 入 PDO 就加一。

### `g_tsn_tx_fail_count`

TSW 发包失败计数。

## 5. 数据流中的几个非对称点

这个工程不是完全对称设计，有几个要注意。

### 5.1 Jetson 侧可发大包，但 EtherCAT 侧未必接得住

Jetson 工具允许发较长 payload，但进入 EtherCAT 前会被截断成 60 字节。

### 5.2 `TSN -> ECAT` 当前是单消息覆盖模型

如果 Jetson 很快连续发多个包，而 EtherCAT 主站消费频率不够：

- ring 可以暂存一部分
- 但 `g_pdo_input_buf` 只有一份
- 每次 `APPL_InputMapping()` 只送出当前最新的一份

如果后续有高吞吐需求，可能要把“单缓冲”改成“应用层队列”。

### 5.3 `RDK -> Jetson` 当前是周期性重复发送

只要主站命令行给了消息，`ecat_gateway_test.c` 会在每个周期持续发送相同 payload。

所以 Jetson 看到大量相同包是符合当前实现的。

## 6. 一句话总结数据流

可以把整个工程的数据流概括为：

- `RDK 输出 PDO -> SSC 输出回调 -> 桥接发送缓冲 -> TSW TX DMA -> Jetson`
- `Jetson 原始帧 -> TSW RX DMA -> IRQ 入环形队列 -> 桥接输入缓冲 -> SSC 输入回调 -> RDK`
