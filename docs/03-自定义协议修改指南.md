# 自定义协议修改指南

本工程当前协议已经比较简单，但它有一个重要特点：同一份协议定义同时存在于三端。

- 固件
- RDK EtherCAT 主站
- Jetson 原始以太网工具

所以“改协议”从来不是改一个头文件就结束，必须按类型成组修改。

## 1. 当前协议边界

共享定义在 `gateway_protocol.h`。

当前关键常量：

- `GATEWAY_ETHERTYPE = 0x88B5`
- `GATEWAY_HEADER_SIZE = 4`
- `GATEWAY_PDO_TOTAL_SIZE = 60`
- `GATEWAY_PDO_MAX_PAYLOAD = 56`
- `GATEWAY_ETH_MAX_PAYLOAD = 1480`

当前结构：

```c
typedef struct __attribute__((packed)) {
    uint8_t  type;
    uint16_t length;
    uint8_t  flags;
} gateway_header_t;

typedef struct __attribute__((packed)) {
    gateway_header_t hdr;
    uint8_t payload[GATEWAY_PDO_MAX_PAYLOAD];
} gateway_pdo_frame_t;
```

注意：

- `length` 是小端。
- `gateway_pdo_frame_t` 当前本质上是 60 字节。
- Jetson 以太网帧虽然可比 60 大，但在 `TSN -> ECAT` 时最终只会截到 60 字节。

## 2. 你可能会改动的协议维度

最常见的是下面五类。

### 2.1 增加新的消息类型

例如增加：

```c
#define GATEWAY_TYPE_CMD 0x10
#define GATEWAY_TYPE_EVT 0x11
```

这类改动最轻。

需要同步修改：

- `gateway_protocol.h`
- `host/jetson_eth/receive_from_board.c` 里的 `type_name()`
- `firmware/ecat_tsn_gateway/gateway_bridge.c` 里接收/发送过滤逻辑
- `host/rdk_ecat_master/ecat_gateway_test.c` 里打印和构帧逻辑

如果只是加类型，不改头大小和 PDO 大小，EtherCAT 映射通常不用动。

### 2.2 增加 flags 语义

例如想用：

- bit0: `ACK_REQ`
- bit1: `IS_FRAGMENT`
- bit2: `IS_LAST_FRAGMENT`

这种改动也比较轻。

需要同步修改：

- `gateway_protocol.h`
- 固件收发解析逻辑
- RDK 构帧和打印逻辑
- Jetson 发包/收包工具

如果只是重定义现有 `flags` 位，不需要改 PDO 大小。

### 2.3 修改 EtherType

如果不想再用 `0x88B5`，可以换成自己的私有 EtherType。

需要同步修改：

- `gateway_protocol.h`
- `gateway_bridge.c` 里的 RX 过滤
- Jetson 发包/收包工具
- 你的抓包命令

例如抓包过滤也要改：

```bash
sudo tcpdump -i enp4s0 -e ether proto 0x88b5
```

## 3. 最敏感的改动：修改头大小或 PDO 总长度

这类改动影响最大。

### 3.1 只改头字段，但总长度不变

例如你把 4 字节头改成另外一种 4 字节布局：

- 仍然 4 字节
- PDO 仍然 60 字节

这时你主要改：

- `gateway_protocol.h`
- 固件解析和构帧逻辑
- RDK 解析和构帧逻辑
- Jetson 工具解析和构帧逻辑

SSC PDO 映射可以不变。

### 3.2 改头大小，导致有效 payload 改变

例如头从 4 字节变成 8 字节，而 PDO 仍想保持 60 字节。

这时要改：

- `gateway_protocol.h`
- 所有用到 `GATEWAY_HEADER_SIZE` 和 `GATEWAY_PDO_MAX_PAYLOAD` 的代码
- `gateway_bridge.c`
- `gateway_app.c`
- `ecat_gateway_test.c`
- `send_to_board.c`
- `receive_from_board.c`

如果只是总大小仍然 60，SSC 里的 60 字节映射通常还能复用。

### 3.3 改 PDO 总长度

例如你想把 EtherCAT 侧从 60 字节扩到 128 字节。

这是全工程联动修改，必须同时动下面这些地方：

1. `gateway_protocol.h`
   - `GATEWAY_PDO_TOTAL_SIZE`
   - `GATEWAY_PDO_MAX_PAYLOAD`
2. `firmware/ecat_tsn_gateway/gateway_bridge.c`
   - `g_pdo_input_buf`
   - `g_pdo_output_buf`
   - copy 长度和截断逻辑
3. `firmware/ecat_tsn_gateway/gateway_bridge.h`
   - extern 数组定义
4. `firmware/ecat_tsn_gateway/application/gateway_app.c`
   - `memcpy(..., 60)` / `memset(..., 60)` 全部改成新长度
5. `host/rdk_ecat_master/ecat_gateway_test.c`
   - `memset(out, 0, GATEWAY_PDO_TOTAL_SIZE)`
   - 打印和 payload 上限判断
6. `firmware/ecat_tsn_gateway/SSC/Src/digital_ioObjects.h`
   - 重新定义对象长度和映射项
7. `firmware/ecat_tsn_gateway/SSC/ESI/ECAT_IO.xml`
   - 更新 PDO 和对象字典描述
8. `firmware/ecat_tsn_gateway/SSC/Config/HPM_ECAT_IO_Config.xml`
   - 同步配置
9. `firmware/ecat_tsn_gateway/SSC/Src/eeprom.h`
   - EEPROM 镜像要与 ESI/对象字典一致

这一步改完后，主站通常需要重新扫描从站，TwinCAT/SOEM 的缓存也要刷新。

## 4. 推荐的改协议方法

最稳妥的做法是按下面顺序改。

### 第一步：先定“链路预算”

先决定：

- 只改消息语义，还是要改长度。
- EtherCAT 方向能接受多大 PDO。
- TSN 方向是否需要支持大于 56 字节的负载。

如果 Jetson 侧要传大于 56 字节的数据到 RDK，而你又不打算改 PDO 大小，那当前实现会被截断，设计上就是不成立的。

### 第二步：先改共享头文件

先从 `gateway_protocol.h` 下手，统一定义：

- 新 type
- 新 flags
- 新头大小
- 新 payload 上限

### 第三步：分别改三端适配逻辑

#### 固件侧

主要看：

- `gateway_bridge.c`
- `gateway_app.c`

#### RDK 主站侧

主要看：

- `ecat_gateway_test.c`

#### Jetson 工具侧

主要看：

- `send_to_board.c`
- `receive_from_board.c`

### 第四步：如果改了 PDO 结构，再改 SSC 元数据

需要一起改：

- 对象字典
- ESI
- EEPROM 镜像

这是 EtherCAT 工程里最容易漏的部分。

## 5. 一个最常见的自定义示例

假设你要定义一个命令包：

```text
type   = 0x10
flags  bit0 = 是否需要应答
payload[0] = cmd_id
payload[1] = seq
payload[2..] = 参数
```

推荐修改步骤：

1. 在 `gateway_protocol.h` 增加：
   - `GATEWAY_TYPE_CMD`
   - `GATEWAY_FLAG_ACK_REQ`
2. 在 `send_to_board.c` 增加命令行参数，允许指定 `type/flags`。
3. 在 `gateway_bridge.c` 放宽过滤，允许 `CMD` 类型透传。
4. 在 `ecat_gateway_test.c` 里增加命令构帧分支。
5. 在 `receive_from_board.c` 里补充 `type_name()`。

如果只是这样，不改长度，EtherCAT 映射层不用重做。

## 6. 如果你要做可靠传输，需要再补的东西

当前协议本质上是“尽力而为”的应用层透传，没有完整的可靠性机制。

如果你要做可确认协议，建议补这些语义：

- `seq`
- `ack_seq`
- `timeout`
- `retransmit`
- `duplicate detect`

实现位置建议：

- 协议字段定义在 `gateway_protocol.h`
- 状态机优先放在应用层，不要塞进 TSW IRQ
- 固件桥接层只负责搬运，不负责复杂事务

## 7. 改协议时最容易踩的坑

### 坑 1：只改了头文件，没改 SSC 元数据

结果通常是：

- SOEM 读到的位宽不对
- PDO 映射长度不一致
- 从站进不了 `SAFE-OP/OP`

### 坑 2：Jetson 发了大包，以为 RDK 一定能收到全包

当前不是这样。

`TSN -> ECAT` 方向在 `gateway_bridge.c` 里有明显截断：

- 只保留以太网 payload 中的前 60 字节
- 其中真正 payload 只有 56 字节

### 坑 3：忽略最小以太网帧长度

如果你重写 `ECAT -> TSN` 发包逻辑，别把最小 60 字节补齐删掉。

### 坑 4：只改 ESI，没改 EEPROM 镜像

HPM 这套 SSC 工程里，ESI、对象字典和 EEPROM 镜像必须一致，否则现场行为会很混乱。

## 8. 推荐原则

如果只是做业务协议演进，优先遵守这两个原则：

1. 尽量不改 `GATEWAY_PDO_TOTAL_SIZE`
2. 尽量保持 `gateway_header_t` 固定长度

这样成本最低，联调风险最小。

只有在确实需要更大负载时，再去动 PDO 长度和 SSC 元数据。
