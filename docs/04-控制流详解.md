# 控制流详解

本文按“固件侧、RDK 主站侧、Jetson 工具侧”分别说明控制流。

## 1. 固件侧控制流

固件主入口在 `firmware/ecat_tsn_gateway/main.c`。

## 1.1 启动阶段

### 步骤 1：板级初始化

执行：

- `board_init()`
- `board_timer_create(1, timer_isr)`
- `full_port_lcd_init()`

目的：

- 初始化时钟、外设、串口打印和 1ms 定时节拍。

### 步骤 2：EtherCAT ESC 相关初始化

执行：

- `board_init_ethercat(HPM_ESC)`
- `board_init_switch_led()`
- 设置 `HPM_ESC->PHY_CFG0` 的 PHY offset

目的：

- 让 ESC 外设和板载 PHY 处于正确连接关系。

### 步骤 3：TSN 交换机初始化

执行：

- `full_port_tsn_init()`
- `board_tsw_phy_set(PORT1/2/3, true)`
- `gateway_tsn_init_mm2s_dma()`
- `gateway_tsn_force_1000m()`

目的：

- 启动 TSW 基础能力。
- 启动外部 PHY。
- 初始化发送 DMA。
- 强制所有端口进入稳定的 1000M/GMII 模式。

### 步骤 4：桥接层初始化

执行：

- `gateway_bridge_init()`

这个函数会做：

1. 初始化 `g_jetson_to_rdk_ring`
2. 设置 MAC lookup table
3. 配置广播和未知帧行为
4. 提交所有 RX DMA 描述符

### 步骤 5：ESC 硬件初始化

执行：

- `ecat_hardware_init(HPM_ESC)`

如果失败，固件直接停住。

### 步骤 6：SSC 初始化

执行：

- `MainInit()`

这一步后，EtherCAT 状态机、对象字典、PDO 管理都开始生效。

### 步骤 7：EEPROM 仿真回调挂接

如果启用 EEPROM 仿真，会挂接：

- `pAPPL_EEPROM_Read`
- `pAPPL_EEPROM_Write`
- `pAPPL_EEPROM_Reload`
- `pAPPL_EEPROM_Store`

### 步骤 8：PDO 映射计算

执行：

- `APPL_GenerateMapping(&nPdInputSize, &nPdOutputSize)`

作用：

- 让固件在启动时打印当前 PDO input/output 大小，确认对象字典和映射一致。

### 步骤 9：启用 TSN 接收中断

执行：

- `full_port_irq_tsn0_init(tsn_irq_callback)`

TSN 收包进入中断驱动模式。

## 1.2 固件主循环阶段

主循环本体：

```c
while (bRunApplication == TRUE) {
    MainLoop();
    gateway_bridge_poll();
    ...
}
```

这两步是整个固件控制流的核心。

### `MainLoop()`

它属于 SSC 主循环，主要负责：

- EtherCAT ESM 状态机推进
- Mailbox 处理
- SyncManager 处理
- 触发 PDO 更新
- 在合适时机调用：
  - `APPL_OutputMapping()`
  - `APPL_InputMapping()`

### `gateway_bridge_poll()`

它属于网关桥接逻辑，顺序固定：

1. `gateway_forward_ecat_to_tsn()`
2. `gateway_forward_tsn_to_ecat()`

注意这里是轮询式，不是在 SSC 回调里直接发包。

## 1.3 固件中断控制流

### 1ms 定时器中断

`timer_isr()` 每 1ms 执行一次。

作用：

- 累加 `10ms/100ms/1000ms` 计数器
- 给主循环打印和 LED 心跳提供节拍

### TSN 接收中断

IRQ 回调：

- `tsn_irq_callback()`
- `gateway_tsn_rx_isr()`

它的流程是：

1. 检查 RX DMA 是否有完成事件
2. 读取响应描述符
3. 找到对应 `recv_buff[id]`
4. 从偏移 `16` 处取真实以太网帧
5. 检查 EtherType
6. 如果是网关帧：
   - 学习 Jetson MAC
   - 推入 `g_jetson_to_rdk_ring`
7. 重新提交 RX 描述符
8. 清中断标志

中断里只做必要动作，不直接碰 SSC。

## 1.4 SSC 回调控制流

SSC 关键回调在 `gateway_app.c`。

### `APPL_StartOutputHandler()`

当从站开始接收主站输出时触发。当前主要用于确认主站已经开始正常驱动 PDO。

### `APPL_OutputMapping(UINT16 *pData)`

这是 `RDK -> HPM` 控制流上的关键点。

调用时机：

- `MainLoop()` 检测到新的输出 PDO 时

动作：

1. 把 `pData` 中的 60 字节复制到 `g_pdo_output_buf`
2. 置位 `g_pdo_output_updated = true`

这相当于把 SSC 层收到的主站输出交给桥接层。

### `APPL_InputMapping(UINT16 *pData)`

这是 `HPM -> RDK` 控制流上的关键点。

调用时机：

- `MainLoop()` 需要更新输入 PDO 时

动作：

1. 如果 `g_pdo_input_updated == true`
   - 把 `g_pdo_input_buf` 复制到 `pData`
   - 清除 `g_pdo_input_updated`
2. 否则写 0

这说明当前实现是单条消息消费式，而不是队列式 PDO 缓存。

## 2. RDK 主站控制流

入口在 `host/rdk_ecat_master/ecat_gateway_test.c`。

## 2.1 启动阶段

### 步骤 1：解析参数

- 网卡名
- 可选消息字符串

### 步骤 2：SOEM 初始化

执行：

- `ecx_init(&g_context, ifname)`

### 步骤 3：扫描从站

执行：

- `ecx_config_init(&g_context)`

### 步骤 4：查找目标从站

按下面条件匹配：

- `Vendor ID = 0x0048504D`
- `Product Code = 0x00000001`

### 步骤 5：PDO 映射和 DC 配置

执行：

- `ecx_config_map_group(...)`
- `ecx_configdc(...)`

### 步骤 6：状态机切换

顺序是：

1. `PRE-OP`
2. `SAFE-OP`
3. `OP`

前两步用：

- `wait_for_state()`

最后一步用：

- `wait_for_op_with_pdo()`

`wait_for_op_with_pdo()` 的特别之处是：

1. 在请求 OP 前先发一次 PDO
2. 进入等待循环后持续发 PDO
3. 周期性重新写 OP 请求

这就是为什么当前从站能稳定进 OP。

## 2.2 运行阶段

主线程只负责等待退出。

真正的 cyclic exchange 在 `cyclic_task()` 线程里。

循环逻辑：

1. `ecx_receive_processdata()`
2. 如果 `sl->inputs` 存在，解析输入 PDO 并打印 Jetson 方向数据
3. 调用 `prepare_output_frame()` 填充输出 PDO
4. `ecx_send_processdata()`
5. `usleep(10000)`

这意味着当前主站周期大约是 10ms。

## 2.3 主站退出阶段

退出时：

1. 等待线程结束
2. 把从站状态写回 `INIT`
3. `ecx_close()`

## 3. Jetson 工具控制流

## 3.1 `send_to_board.c`

流程非常直接：

1. 打开原始 socket
2. 读取本机网卡 index 和源 MAC
3. 构造：
   - 目标 MAC = 板子 CPU MAC
   - 源 MAC = 本机网卡 MAC
   - EtherType = `0x88B5`
   - `gateway_header_t`
   - payload
4. 调用 `sendto()`

## 3.2 `receive_from_board.c`

流程是：

1. 打开原始 socket
2. 绑定到指定网卡
3. 循环 `recvfrom()`
4. 过滤 EtherType `0x88B5`
5. 打印源 MAC、type、length、flags、payload

## 4. 三端联动时序

一个完整的正常时序可以概括为：

1. 固件上电，完成 TSN/ESC/SSC 初始化。
2. RDK 主站启动并把从站推到 `OP`。
3. `APPL_StartOutputHandler()` 被触发。
4. `APPL_OutputMapping()` 周期性收到主站输出。
5. 固件把输出 PDO 转成 TSN 帧发给 Jetson。
6. Jetson 发回一个网关帧到 CPU MAC。
7. 固件 TSN IRQ 收到它，写入 `g_pdo_input_buf`。
8. 下一次 `APPL_InputMapping()` 把它送进输入 PDO。
9. RDK 在 `ecx_receive_processdata()` 后读到并打印。

## 5. 一个关键的时序细节

如果 Jetson 在 RDK 还没进入真正的 cyclic receive-print 阶段之前就发包，可能出现：

- 固件已经收到并写进 PDO
- `APPL_InputMapping()` 也已经消费掉
- 但 RDK 后续打印线程还没开始

最终表现就是：

- 板子日志里有 `TSN->ECAT`
- RDK 终端没看到打印

这不是丢包，而是当前控制流决定的“打印时机晚于消息消费时机”。
